# 3.1 Authentication & Authorization

**Description:** The system must authenticate all users via OAuth 2.0 and authorize their actions according to an assigned role.

| ID | Requirement | Priority |
|---|---|---|
| FR-AUTH-1 | The system shall authenticate all interactive users using the OAuth 2.0 Authorization Code flow with PKCE against the organization's identity provider. | Must |
| FR-AUTH-2 | The system shall issue short-lived access tokens with refresh tokens and store session state in secure, HTTP-only cookies. | Must |
| FR-AUTH-3 | The system shall support configurable idle-timeout and absolute-timeout session policies. | Should |
| FR-AUTH-4 | The system shall provide, at minimum, Administrator, HR Reviewer/Uploader, and Manager/Read-Only roles, each scoped to specific permitted actions. | Must |
| FR-AUTH-5 | The system shall support restricting an HR Reviewer/Uploader's employee search and record visibility to a specific department, where configured. | Should |
| FR-AUTH-6 | The system shall provide a login page that redirects to the identity provider and clearly surfaces expired-session, access-denied, and account-lockout conditions. | Must |
| FR-AUTH-7 | The system shall provide a basic registration page for provisioning internal accounts where self-service registration is enabled. | Could |
| FR-AUTH-8 | The system's architecture shall support adding the organization's corporate identity provider as a federated SSO source without requiring a redesign of the authentication layer. | Should |
