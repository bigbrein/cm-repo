# 3.4 Document Metadata & Naming Convention

**Description:** Every CM document must carry a consistent, system-generated metadata set and a standardized, collision-free document name.

| ID | Requirement | Priority |
|---|---|---|
| FR-MD-1 | The system shall automatically generate a unique Document ID for every CM document. | Must |
| FR-MD-2 | The system shall automatically generate a Document Name using the format `CM-{EmployeeInitials}{EmployeeID}-{MMYY}{Sequence}`, where MMYY is the two-digit issue month and year and Sequence is a zero-padded, monthly-resetting sequence number (e.g., `CM-JD12345-0526001`). | Must |
| FR-MD-3 | The Sequence component shall reset to `001` at the start of each calendar month and shall be generated within a database transaction (e.g., a per-month counter with row-level locking, or a database sequence keyed by month) to guarantee uniqueness under concurrent uploads. | Must |
| FR-MD-4 | The system shall reject or retry document name generation in the event of a detected collision, such that no two documents share a name within the same month. | Must |
| FR-MD-5 | The system shall capture CM Type, Valid Period (Months), and Date Issued as user-entered fields. | Must |
| FR-MD-6 | The system shall calculate Expiry Date as Date Issued plus Valid Period (Months). | Must |
| FR-MD-7 | CM Type shall be maintained as a configurable lookup list (initially: Written Warning, Verbal Warning, Final Warning) rather than a hard-coded value, so new types can be added without a code change. | Should |

**Reference naming convention:**

```
CM-{EmployeeInitials}{EmployeeID}-{MMYY}{Sequence}
```

**Example:**

```
CM-JD12345-0526001
```
